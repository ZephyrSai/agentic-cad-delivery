    Business case & pilot plan / prepared for the design delivery board

    Prompt to Drawing Set

    An agentic AI framework that takes parameters from discipline experts and vertical owners and produces coordinated, checkable, defensible CAD & BIM deliverables — from concept layout through ELV and shop drawings.

    Part A

    The process as it is

    100 discrete steps, 9 parameter classes, 7 check layers, 6 authorities.

    Part B

    The framework

    25 agents over a governed parameter graph. Agents emit operations, never raw geometry.

    Part C

    The POC

    22 weeks, one building, one or two workflows, four hard gates. Estimated at ₹45–55 lakh.

    Part D

    The exposure

    Liability, E&O exclusions, licensing and data residency — priced in, not wished away.

    Approach

    Prompt to CAD, built to production standard. Agents take parameters from the experts who own them, operate a validated parameter model, and prove their own work against machine-readable rules — so what comes out is coordinated, checkable and ready for a signature. This deck sets out how it is built, what it takes over and what it costs.

    The cost and timeline in this set are for a proof of concept, not a full delivery programme, and are estimates only. See PL-409 for the basis and its limits. Navigate with the left and right arrow keys, or space. Press Esc or use Index for the sheet list.

    G-002 / Executive summary

    Seven propositions

    What follows is the whole argument in one sheet. Everything after it is evidence, detail or cost.

    • 01
      The bottleneck is not drafting. It is parameter settlement. A draftsman turns a settled decision into geometry in hours. Getting nine disciplines to settle that decision takes weeks. Automate the drafting alone and you shave the smaller half of the clock.
    • 02
      So the product is a parameter graph, not a chatbot. Every value an expert or vertical owner would have said in a meeting becomes a typed, versioned, owned entry in one Project Parameter Graph. Agents read and write only that. Drawings are a rendering of it.
    • 03
      Agents speak operations, not raw geometry. Agents emit typed operations — route_containment, place_device_array, generate_sheet — executed by Revit, AutoCAD or IFC toolchains, so every action is replayable, diffable and attributable. Each agent stands in for one named desk role; AR-302A and AR-302B set out how much of that role’s day it absorbs.
    • 04
      Verification is the product, generation is the commodity. Generation is now cheap and getting cheaper. What a top agency sells is a set someone will stamp. Build the checking layer first — IDS rule packs, clash, code compliance, drawing-standards QA — and generation can be swapped out yearly.
    • 05
      Seven integrations are non-negotiable. Everything else can wait. CDE, authoring-engine control, neutral exchange (IFC), machine-readable requirements (IDS), issue exchange (BCF), identity + immutable audit, and the agent orchestration layer. Procore, P6, ERP and e-permit portals are Phase 2.
    • 06
      The connectors are the engine, even at pilot stage. Building interfaces to the CDE, to Revit and AutoCAD, to IFC, BCF and the audit log is, in substance, building the final product. It is roughly half our engineering effort, it is written once, and it carries forward in full — which is why a pilot that skips it produces a demo rather than a foundation.
    • 07
      Target L2 autonomy in the pilot, not L4. Agent produces, machine checks, human approves at defined gates. The engineer of record still signs. Insurers are writing AI exclusions right now — the audit trail is what keeps the work insurable.

    Part A / PR-100 / The process as it is

    How a drawing set is actually born

    Seven stages, each ending in an information exchange through the common data environment. The red markers are the points where somebody outside the design team has the power to stop you.

    Contractual spine

    EIR → pre-appointment BEP → post-appointment BEP → MIDP → TIDP per task team. If this chain is vague, no amount of automation saves the programme.

    The one hard rule

    Shared coordinates, true north, level datum and units are fixed once, published, and never renegotiated. Every automation downstream assumes them.

    Where ELV sits

    ELV is defined at concept, ignored until detailed design, then compressed into the shop-drawing window. It is the discipline with the worst ratio of decisions to time.

    A parameter is agreed verbally, never written, and two disciplines model different values. Discovered at federation, six weeks later.

    Sequencing reality

    Civil Defence and the electricity and water authority submissions are gated on earlier municipality clearance. A comment at step 62 can invalidate work back at step 30.

    Agent leverage

    Pre-flight compliance: run the authority’s own checklist as a rule pack before submission. The value is in the resubmissions never raised, not in filing faster.

    Do not automate

    Submission and correspondence with authorities stays human and named. An agent drafts; a licensed engineer signs and transmits.

    Layers 1, 2, 3 and 6 are roughly 60–70 % of check effort on a typical set and are entirely mechanical.     Layer 7 never moves

    The seal is a personal attestation. Licensing boards hold the named professional responsible for verifying accuracy and meeting the standard of care whether or not AI assisted. Every architecture decision in Part B is downstream of protecting that signature.

    Part B / TH-201

    The generation pipeline

    This is the path from something an expert says to a sheet somebody signs. Each stage is a real artefact: an intent, a set of parameters, a list of operations, a model, a check report, an approval. Because every stage is recorded, any drawing can be traced back to the values and the person behind it.

    Reproducible

    The operation list is stored, so the same parameters produce the same drawing today and in a review three years from now. That is what makes a set defensible long after the team has moved on.

    Unit-safe

    Operations carry their units, ranges and enumerations. A clearance in the wrong unit or a bend radius outside the permitted range does not compile, so it never reaches a sheet.

    Attributable

    Every element can name the parameter versions, the agent, the model build and the person who approved it. That record is what keeps the work auditable and insurable.

    Part B / TH-202 / The core object

    The Project Parameter Graph

    One typed, versioned, owned store of every decision that constrains the design. Experts write to it. Agents read from it and never invent values. Drawings are a rendering of it. Change propagation stops being a memory exercise.

    Anatomy of one node

    id       ELV.CCTV.coverage_target
    value     0.95 (fraction of public floor area)
    unit      ratio
    owner     ELV lead — countersigned by client security
    source    Security authority spec cl. 4.2 / minutes 2026-03-11
    status    FROZEN at gate S3
    version   v4 — supersedes v3 (0.90)
    depends   ARCH.space.public_area, ELV.CCTV.camera_family
    affects   41 elements, 6 sheets, 2 schedules, 1 authority pack

    What it buys

    • Impact analysis becomes a query, not a meeting.
    • A freeze is enforceable: agents refuse to act on unfrozen inputs at a gate.
    • Every drawing carries the parameter versions it was generated from, in its own title block metadata.
    • Cross-discipline conflicts surface at parameter-entry time, weeks before federation.

    Part B / AR-300

    Reference architecture — four layers

    Experts and vertical owners feed the intake layer. The ledger is the only source of truth. Generation is deliberately replaceable. Verification runs on every change and can veto.

    Layer 2 is the asset

    If you build one thing, build the ledger. Model vendors, CAD versions and agent frameworks will all churn. The parameter graph and its provenance log are what compounds.

    Layer 3 is a commodity

    Engine adapters behind one operation interface. When Revit’s own assistant or a better generator arrives, you swap an adapter, not the system.

    Layer 4 has a veto

    No artefact reaches a human gate without a check report attached. A failed check blocks issue — it does not produce a warning that gets clicked through.

    Autonomy is granted per agent, per deliverable type, and only after that agent has a measured track record on that deliverable. Nothing starts above L1.

    L3Gated autonomyProduces, self-checks, corrects and re-runs until cleanApproves at defined gates only; audits a sampleZero escaped defects at IDC across a full stage

    The four gates that never move

    • Parameter freeze. A named owner freezes each parameter class at each stage. Agents refuse to operate on unfrozen inputs past that point.
    • Design intent. A discipline lead accepts that the produced solution is the right solution, not merely a compliant one.
    • Issue for approval. A licensed engineer stamps. This is a personal attestation and is never delegated to a system.
    • Change acceptance. Any change with cost, programme or safety impact is a human decision, with the blast radius shown.

    The insurance constraint, stated plainly

    Professional indemnity carriers are actively writing AI exclusions into E&O and D&O wordings, with new exclusion forms in effect from January 2026 and at least one carrier issuing an absolute AI exclusion naming specific tools. The distinction carriers are drawing is between AI-assisted work that a licensed professional reviews, verifies and seals — generally still covered — and autonomous output that no one verified.

    Consequence for this programme: the evidence pack and the immutable audit log are not nice-to-have engineering hygiene. They are the artefact that demonstrates the review actually happened. Brief your broker before the pilot starts, not after.

    Part B / AR-306

    Guardrails: build the checker before the generator

    Every guardrail below is buildable in the pilot window with existing standards and tooling. None of them depend on a model getting smarter.

    G1 — Typed operations only

    Agents cannot write geometry directly. The operation schema validates units, ranges, enumerations and references before anything touches a model. An out-of-range argument is a compile error, not a drawing.

    G2 — Frozen-input enforcement

    Operations declare the parameters they consume. If any is unfrozen at the current gate, execution is refused and the missing decision is routed to its owner.

    G3 — Evidence or no issue

    A deliverable cannot reach a human gate without IDS, clash, code and drawing-QA reports attached. Reviewers see evidence first, geometry second.

    G4 — Determinism & replay

    The op-list is stored. Re-running it on the same parameter versions reproduces the same model, byte-comparable. This is what makes the work auditable years later.

    G5 — Adversarial self-check

    A second, differently-prompted agent reviews the first agent’s output against the requirement set before a human sees it. Cheap, and it catches the confident errors.

    G6 — Blast-radius reporting

    Every change presents the elements, sheets, schedules and packages it invalidates, before it is committed. No silent staleness.

    G7 — Human-authored rule packs

    Code rules are written and version-controlled by named engineers, reviewed like code. An agent may propose a rule; it may never author one into production.

    G8 — Data boundary

    Client models, authority correspondence and security-system layouts are commercially and physically sensitive. Fix the residency, retention and no-training terms of the model provider before week one, and record which model build produced each artefact.

    Sequencing consequence

    Build order for the pilot is guardrails and checkers first, generators second. A checking agent that is wrong produces a false alarm a human dismisses in seconds. A generating agent that is wrong produces a drawing someone builds from. The asymmetry should decide the schedule, and on sheet PL-402 it does.

    Why not wait for the vendors

    Autodesk will keep shipping assistants, and they will be good at what sits inside one authoring tool. The parameter ledger spans nine disciplines, six authorities and two contract parties. No authoring-tool vendor is positioned to own that, and it is where the defensible advantage is.

    Why not buy a platform

    Several vendors will sell an “AI BIM platform” in the next eighteen months. Buy one before you have your own parameter schema and rule packs and you will have outsourced the only part that was ever yours.

    Why not build everything

    A firm that builds its own clash engine or CDE has confused the hard problem with the visible one. Build exactly two things: the ledger and the operation interface.
